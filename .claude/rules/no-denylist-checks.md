# 列挙で塞ぐ検査を blocking 保証に使わない

**原則の正典は `~/.claude/rules/verify-checks-by-breaking.md` の「除外リスト」項目**（Claude runtime 専用の運用依存。
別 runtime では参照不能なので、その場合は本ファイルの判定手順だけで判定する）。
**原則の文言が食い違ったら共通 rule が勝つ。** ここは当PJの**発火条件・判定手順・実測・実行契約**だけを持つ。

**発火条件（機械的）**: 「望ましくない書き方・名前・経路・状態を検出する」検査
（lint / AST 走査 / 契約テスト / write barrier / ゲート）を**設計または実装に最初に着手する時点**で適用する。
**PR の有無を問わない**（ローカル実装・直接 commit・探索用 advisory も対象。
「PR に載せるかは未定」で着手した実装が、止めたい工数をすでに消費する）。
重要度・行数・「小さい修正だから」で判断しない。

## 判定手順（自己申告で終わらせない）

**allow / deny のラベルでは二分できない**。「登録済みストア名の集合だけ許す」は allow を名乗るが、
照合が basename の一致である限り hard link・別マウント・大小文字別名で破れる。
判定するのは**集合の向きではなく、識別の閉性**である。

着手前に次を書き、**書いた本人とは別の判定者が裁定する**。裁定が済むまで実装に着手しない。

1. **守る対象の意味的な母集団**を1行で書く（何を1件と数えるか）
2. **判定に使う識別**は何か（名前 / 文字列 / 構文形 / sink の種類 / inode / 不変 ID / 登録済み識別子そのもの）
3. **許可集合が母集団に対して閉じている根拠**（閉じている＝同じ実体を指す別の表現が存在しない）
4. **未登録の入力を1件作った陰性試験**の結果
5. 指摘への対処が「**名前・構文・sink の種類を1つ足す**」でしかできないなら、その検査は**閉じていない**

**閉じていない**と裁定されたら blocking 保証に使わない。とれる手は次のいずれか:

- **実体の同一性で判定し直す**（inode・不変 ID・登録済み識別子）
- **静的検査を諦め、実行時の境界・権限分離・入力面の縮小へ寄せる**
  （`verify-checks-by-breaking` の「欠陥を決定論チェックへ翻訳する一手」は省略できない。
  検査を作らないことは、その一手を放棄してよいという意味ではない）
- **advisory として残す**。この場合、本文・テスト名・PR 本文に
  **「既知の種別のみ検出・迂回可能」**と明記し、非検出範囲・補完防御・owner・撤去条件を**人間が承認**する。
  **「新しい◯◯を足すと落ちる」と書いてよいのは、閉じていると裁定された検査だけ**

**「暫定で置いて後で閉じる」は選択肢に入れない**（検査が緑である限り誰も閉じにこない）。

## 走査範囲も同じ基準で見る

`rglob("*.py")` のような拡張子ベースの収集は、拡張子なしの実行スクリプトを静かに落とす。
**収集範囲は「実行される可能性のあるもの全部」から始め、除外に根拠 file:line を要求する。**

## 既存の閉じていない検査に当たったとき

**「次の抜け道を塞ぐ」修正を追加レビュー巡で解決しようとしない。**
`review-gate` スキル（`~/.claude/skills/review-gate/`）の「同一の欠陥族への後追いパッチが2巡続いたら打ち切り」が先に効く。
巡数・本数の正典は `~/.claude/rules/review.md`。
塞ぎ続けるのではなく、**閉じた判定への作り直し・撤去・advisory への降格**のどれかへ送る。
