# 禁止を数え上げて塞ぐ検査を作らない

正典: `~/.claude/rules/verify-checks-by-breaking.md`（allowlist / 除外リストの項目）。
ここは当PJでの発火条件と実測を持つ。原則の文言は正典を書き換える。

**発火条件（機械的）**: 「望ましくない書き方・名前・経路を検出する」検査（lint / AST 走査 /
契約テスト / write barrier / ゲート）を**追加または拡張する PR を書き始めた時点**で適用する。
重要度・行数・「小さい修正だから」で判断しない。

- **着手前に、その検査が次のどちらの型かを1行で宣言する。宣言の無い検査を PR に含めない**
  - **denylist 型**＝ 悪い形を列挙して弾く（禁止する関数名・パス表現・文字列・sink の種類を数え上げる）
  - **allowlist 型**＝ 許す形を全列挙し、**完全一致しないものを落とす**（役割宣言・登録・宣言済みの識別子）
- **denylist 型と判定したら、まず allowlist 型へ反転できるかを検討する。反転できないなら検査を作らない**。
  作らないと決めた事実と、その結果残るリスクを設計文書の残存リスク節に書く。
  **「暫定で denylist を置いて後で反転する」は選択肢に入れない**（反転の実行契約を書いても、
  検査が緑である限り誰も反転しにこない）
- **反転の判定は「悪い形を全部列挙できるか」ではなく「良い形を全部列挙できるか」で行う**。
  後者が列挙できるなら反転可能。前者が列挙できるという感触は、denylist 型では必ず誤りである
- **denylist 型の検査を含んだまま PR 本文に「新しい◯◯を足すと落ちる」と書かない**。
  書けるのは allowlist 型だけ。denylist 型は **「既知の種別のみを検出する advisory。迂回可能」**と書く
- **既存の denylist 型の検査に対する「次の抜け道を塞ぐ」修正を、追加レビュー巡で解決しようとしない**。
  `review-round-cap.md` の族2巡打ち切りが先に効く。塞ぎ続けるのではなく、反転・撤去・残存リスク明記のどれかへ送る
- **走査範囲そのものも denylist になりうる**。`rglob("*.py")` のような拡張子ベースの収集は、
  拡張子なしの実行スクリプトを静かに落とす。**収集範囲は「実行される可能性のあるもの全部」から
  始めて、除外に根拠 file:line を要求する**

**未実測**: この rule を置くことで、実際に denylist 型の検査の着手が止まるかは測っていない。
**実行契約**: 起点=2026-09-03 ／ 1件の定義＝「望ましくない形を検出する検査を追加・拡張する PR」1本 ／
再測条件＝3件到達 または 2026-10-31 の早い方 ／ 実行者＝頭 ／ 判定者＝ユーザー ／
判定基準＝3件中1件以上で型の宣言が行われ、denylist と判定したものが反転または不作成に倒れていれば維持 ／
期限超過時＝発火実績0件なら本 rule の撤去をユーザーへ提起する
