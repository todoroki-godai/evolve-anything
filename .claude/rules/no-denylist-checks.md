# 列挙で塞ぐ検査を blocking 保証に使わない

原則の正典は `~/.claude/rules/verify-checks-by-breaking.md` の「除外リスト」項目（Claude runtime 依存。食い違ったら共通 rule が勝つ）。ここは当PJの発火条件を持つ。

- **発火条件（機械的）**: 「望ましくない書き方・名前・経路・状態を検出する」検査（lint / AST 走査 / 契約テスト / write barrier / ゲート）を**設計または実装に最初に着手する時点**で適用する。**PR の有無を問わない**（ローカル実装・直接 commit・探索用 advisory も対象）。重要度・行数・「小さい修正だから」で判断しない
- **名前・文字列・構文形・sink の種類で同一性を判定する検査は blocking にしない**。この4つは実測で破れている（実測は refs）。**判定に何を使っているかを1行で書く**。書けないなら blocking にしない
- **健全さの判定手順を自分で書いて自分で通さない。** blocking へ昇格させるかは**書いた本人とは別の人間が裁定する**。裁定の材料は、完成条件の「守る対象」「信頼境界」と、**その検査を通したまま守る対象を壊す入力を実際に構成した結果**（構成できた時点で blocking 不可）。**「閉じていることの証明」を求めない**（2026-09-03 実測: 証明の様式を定めるほど、それを満たす申告文が構成された）
- **blocking にしないと決めたら、代わりに何で守るかを同じ PR で決める**（実行時の境界・権限分離・入力面の縮小・人間承認）。共通 rule の「欠陥を決定論チェックへ翻訳する一手」は省略できない。advisory として残す場合は、本文・テスト名・PR 本文に**「既知の種別のみ検出・迂回可能」**と明記する。**「新しい◯◯を足すと落ちる」と書いてよいのは blocking へ昇格したものだけ**。「暫定で置いて後で閉じる」は選択肢に入れない
- **走査範囲も同じ基準で見る**（`rglob("*.py")` は拡張子なしの実行スクリプトを静かに落とす）。収集範囲は「実行される可能性のあるもの全部」から始め、**除外に根拠 file:line を要求する**
- **既存の閉じていない検査に当たったら、「次の抜け道を塞ぐ」修正を追加レビュー巡で解決しようとしない**。`review-gate` スキルの「同一の欠陥族への後追いパッチが2巡続いたら打ち切り」が先に効く（巡数・本数の正典は `~/.claude/rules/review.md`）
- 実測4巡の内訳・レビュー2巡で構成された「手順を満たす申告文」・実行契約・未実測は `.claude/rules/refs/no-denylist-checks.md` を、この rule を再測する／撤去を検討する直前に読む
