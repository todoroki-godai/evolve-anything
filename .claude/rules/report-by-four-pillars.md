# 進捗・残タスクは4つの柱で報告する

残タスク・進捗・優先順位は CLAUDE.md「目指すユーザー体験」の柱1〜4 ごとに現状を示す。issue 番号順・作成日順で並べない（柱の名称と定義は CLAUDE.md が単一ソース。ここに写して二重管理しない）。

**固定の並び**: 柱1 → 柱2 → 柱3 → 柱4 → **健全性** → **後回し**。各レーンは `現状（証拠）／ボトルネック／次の一手` の3点で書く
- **健全性レーンは柱に属さない**（正しさ・安全・テスト基盤・技術的借金）。柱に無理やり紐づけて正当化しない。**柱は優先順位の物差しであって取捨ではない**
- **後回しは理由つきで明示する**。黙って一覧から消さない
- 各柱の現状は**実測値**で書く。目標文をなぞらない（#376 を自分の報告にも適用する）
- **数値をこの rule にも CLAUDE.md にも書かない**。フル報告時に `bin/evolve-audit --growth`（柱3）と `bin/evolve-revert --list`（柱4）を実行して取る。同一セッション内は取得時刻を添えて再利用してよい（毎ターン実行しない）
- **測定手段（#685）**: 柱1〜柱3は `bin/evolve-audit --growth` で取得する（柱4は直前行のとおり `bin/evolve-revert --list`）。柱1主行の確認用セットは git 管理外の共有 DATA_DIR に置くため、**実体を持たないマシンでは測定不能**。調整に使った a0 も git 管理外で、checkout 同梱と共有 DATA_DIR を探す（#602）。**柱2は「実際に反映された改善（直近30日）」の行が正典**（#587 の専用ストア `reflect_apply_events.jsonl` を read 時に照合する。PR #596/#599 で配線済み）。取り消しは申告があったぶんだけ反映する。同じ出力の「**採用した改善（直近30日）**」は**提案の accept という別物なので柱2に流用しない**。申告ベース（`correction_review_seen.jsonl` の `promoted` / `already_reflected`）も照合が無いので使わない。**柱2の行が `measured=False` を示すとき（「測定不能」表示）は数字を書かず、その旨と理由を書く**。柱3は同コマンドによる全 PJ 合算。取得不能なら `not_measured` と書き、推定値で埋めない
- **柱1の読み方（#685）**: 主行は調整に使っていない確認用セットで、正規表現または AI 判定候補が拾った TP の合計。AI 候補は朝の y/n 前で、本番 corrections 保存件数ではない。評価行との一対一突合・現行の判定版/モデル別名/バッチ設定の来歴が確認できないときは主行を「測定不能・理由」とし、a0 の値を繰り上げない。a0 は調整に使ったため上振れしうる参考値で、到達の根拠にしない。旧 `L1捕捉率` は正規表現だけの系列として値と測定不能表示を維持する。目標値は #567 を参照（合計に適用することは #679 のコメントに記録）。
- **コマンドの成否を exit code で判定しない**。`bin/evolve-audit --growth` は生成に失敗しても 0 を返す（実測: 例外を握って本文に「生成に失敗しました」の1行を足すだけ）。**出力本文に「失敗しました」が無いこと＋期待セクションが実在すること**で判定し、欠けていたら `測定不能: <理由>` と書く。古い値で補完しない。他レーンの報告は続ける
- ボトルネックは各柱1件。柱をまたぐものは「共通ボトルネック」を最大1件だけ置き、各柱からそれを参照する（同じものを4回書かない）

**未実測**: この rule を置くことで報告の挙動が実際に変わるかは測っていない。指示文書のロードと遵守は別（#494 と同じ問題）。
