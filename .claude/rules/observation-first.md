# 観測が繋がることを最優先にする

**発火条件（構造で定義する）**: **独立して完了判定できる成果物（issue / PR / 変更単位）を2件以上**挙げて順序・優先度・着手可否を提示し、そのうち2件以上が別のレーンに属するとき。レーンは CLAUDE.md「目指すユーザー体験」の1〜4と健全性レーン（`report-by-four-pillars.md` が正典）。**提示時に各成果物のレーン分類と根拠を1行で書く**。複数 issue を「1件の横断施策」と束ねて件数を1に見せることは非該当理由にならない（束ねた場合は束ねる前の件数で判定する）。1件ずつ処理する運用・「依存関係／緊急度／着手順を決めただけ」への言い換えも同様。

- **配線断の定義**: `writer` / `永続化された記録` / `reader` / `surface された出力` のいずれか1つでも欠ける状態。**空ファイルを作って件数0を読めることは「繋がった」ではない**（意味のあるイベントが1件以上通ることを実データで確認する）。**ただし正典が意図的な非表示と定め、代替のメタ情報を surface している経路は配線断に数えない**（#379 Step 2 の表示淘汰と `display_cull` がこれにあたる）
- **配線断の修理を、その上に載る改善より先に倒す**。配線が切れている間、他の改善は効果を測れず、効いたかを推測で語ることになる
- **「読めなかったのに在庫ゼロと報告する」型は配線断として扱う**。「データ品質問題」「既存機能のバグ修正」への再分類で対象外にしない
- **上位例外**: 安全・正しさ・データ破壊防止の blocking 事項は本 rule より優先する（`report-by-four-pillars.md` の健全性レーン）
- **配線修理は既存契約を弱めてはならない**: dry-run 純度・人間承認・write barrier・データ契約のいずれも緩めない。記録が足りないことを理由に、**既存契約が明示していない新規・追加の永続化を行わない**（既存契約が意図として定めた書込み — pending marker の dry-run 書込み等 — は維持する。消すことも「弱める」にあたる）。y/n なしで採用結果を作る・履歴を自動補完するも同様に禁止
- **#379 の新設凍結は継続する**。凍結対象は CLAUDE.md「新設凍結（#379 Step 1）」の記載すべて（列挙をここに写して二重管理しない）。既にあるものを繋ぐのであって、新設で解決しない
- 優先順位を提示するときは、各項目が「配線を繋ぐ」か「配線の上に載る」かを明示し、後者には**依存する配線と、それが繋がっていることの確認コマンド**を添える
- **正典の分担**: 計測の延期判定は `measure-now-not-later.md`、報告形式は `report-by-four-pillars.md`、本 rule は**配線断の横断優先だけ**を担当する
