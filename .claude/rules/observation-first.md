# 観測が繋がることを最優先にする

**発火条件**: 独立して完了判定できる成果物（issue / PR / 変更単位）について順序・優先度・着手可否を提示するとき、候補に**下の2型のいずれか**が含まれる場合。含まれなければ本 rule は適用しない（無音）。

- **配線断はこの2型だけ**（列挙は閉じている。他の不具合を配線断と呼ばない）。①**取得失敗の握り潰し** = reader が読めていない・一部を落としているのに、在庫ゼロ・件数 N として正常値のように報告される（例外を空配列へ丸める、壊れた行を無言 skip する）②**接続先の食い違い** = writer の書込先と reader の読取先が実行時に別物で、reader は正常終了するため気づけない（実例 ADR-042: hook は plugin-data へ書き prune は fallback から読む）
- **配線断の修理を、その上に載る改善より先に倒す**。配線が切れている間、他の改善は効果を測れず、効いたかを推測で語ることになる
- **「配線断だ」と主張する側に立証義務がある**。①writer の file:line ②記録の実パス ③reader の file:line ④出力先（どの表示に出るか）⑤①〜③の照合に使った確認コマンドと**その結果**、の5点を添える。**5点を書けないものを配線断に分類してはならない**（＝優先を主張できない）。通常の品質改善を言い換えて最優先へ滑り込ませる経路を塞ぐ
- **経路は繋がっているがまだイベントが1件も通っていない状態は配線断ではない**（導入直後の経路を断線扱いにしない）。この状態を「配線断ゆえ最優先」と主張しない
- **配線修理は既存契約を弱めてはならない**: dry-run 純度・人間承認・write barrier・データ契約のいずれも緩めない。記録が足りないことを理由に、**既存契約が明示していない新規・追加の永続化を行わない**（既存契約が意図として定めた書込み — pending marker の dry-run 書込み等 — は維持する。消すことも「弱める」にあたる）。**#379 の新設凍結**（対象は CLAUDE.md の記載すべて）も同様に継続する
- **本 rule は優先順位の一材料であって、安全・正しさ・データ破壊防止の blocking を上書きしない**。報告の形式は `report-by-four-pillars.md` が正典で、本 rule は**配線断の横断優先だけ**を担当する
