# 観測が繋がることを最優先にする

**発火条件（構造で定義する。語句で判定しない）**: **独立して完了判定できる成果物（issue / PR / 変更単位）を2件以上**挙げて順序・優先度・着手可否を提示した時点で、**各候補が配線断（下の①②）の修理に当たるかを判定する**。該当ゼロ件なら本 rule は以降適用しない（分類行も書かない＝通常のフル報告を毎回発火させない）。1件以上あるときだけ以下が発火する。**レーン・柱の分布では判定しない** — 同一レーン内に配線修理と上位改善が並ぶ場合に空振りし（#533 と #516 が実例）、配線と無関係な複数レーンの進捗報告で常時発火するため。束ねて件数を1に見せる・「依存関係／着手順を決めただけ」への言い換えは非該当理由にならない。

- **配線断は3状態を区別して判定する**。①**未接続** = `writer` / `永続化された記録` / `reader` / `surface された出力` のいずれかが欠ける、**または4要素が揃っているのに writer の書込先と reader の読取先が同一でない**（実例 ADR-042: hook は plugin-data へ書き prune は fallback から読む。reader は正常終了するので②にも当たらない）②**取得失敗** = reader が読めていないのに在庫ゼロ・件数0として報告される ③**交通ゼロ** = 経路が繋がり接続先も一致するが、まだ本物のイベントが1件も通っていない。**配線断は①②だけ。③は数えない**（数えると導入直後の経路を永久に断線扱いにする）。③は「交通ゼロ・未検証」として surface する（無音にしない）。**正典が意図的な非表示と定め代替のメタ情報を surface している経路も配線断に数えない**（#379 Step 2 の表示淘汰と `display_cull`）
- **判定に実イベントの生成を要求しない**。①②は**書込先パスと読取先パスの照合**（コードの file:line とパス文字列）で判定する。実データを1件通すことを条件にすると、本 rule 自身の「新規・追加の永続化を行わない」と CLAUDE.md の「適用は必ず人間の y/n」に抵触する
- **「配線を繋ぐ」と分類する側に立証義務がある**。①writer の file:line ②記録の実パス ③reader の file:line ④出力先（どの表示に出るか）⑤①〜③の照合に使った確認コマンドと結果、の5点を添える。**5点を書けないものを配線断に分類してはならない**（＝優先を主張できない）。通常の品質改善を「surface を繋ぐ」と言い換えて確認コマンドなしに最優先へ滑り込ませる経路を塞ぐ
- **配線断の修理を、その上に載る改善より先に倒す**。配線が切れている間、他の改善は効果を測れず、効いたかを推測で語ることになる
- **上位例外はこの3つに閉じる**: ①進行中のデータ破壊・消失 ②秘密情報の漏洩 ③誤った出力が人間の判断を汚染している。**テスト基盤・技術的借金・リファクタ・依存更新は上位例外に含まない**（`report-by-four-pillars.md` の健全性レーンは報告の並びを決めるだけで、本 rule の優先を上書きしない。「健全性だから」で配線修理を後ろへ送れないようにする）
- **配線修理は既存契約を弱めてはならない**: dry-run 純度・人間承認・write barrier・データ契約のいずれも緩めない。記録が足りないことを理由に、**既存契約が明示していない新規・追加の永続化を行わない**（既存契約が意図として定めた書込み — pending marker の dry-run 書込み等 — は維持する。消すことも「弱める」にあたる）。y/n なしで採用結果を作る・履歴を自動補完するも同様に禁止
- **#379 の新設凍結は継続する**。凍結対象は CLAUDE.md「新設凍結（#379 Step 1）」の記載すべて（列挙をここに写して二重管理しない）。既にあるものを繋ぐのであって、新設で解決しない
- 配線断が1件以上あるときは、優先順位の提示で各項目が「配線を繋ぐ」か「配線の上に載る」かを明示し、後者には**依存する配線と、それが繋がっていることの確認コマンド**を添える
- **正典の分担**: 計測の延期判定は `measure-now-not-later.md`、報告形式は `report-by-four-pillars.md`、本 rule は**配線断の横断優先だけ**を担当する
