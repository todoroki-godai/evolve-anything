# 型スキル焼き戻しパイロット（手書きログ・ゼロコード）

> **目的**: cross-PJ 蒸留 Phase 1-3（自動化）を作る前に、「型スキルの存在を可視化したら、実際に型スキルへ**焼き戻す行動**が起きるか」を手作業で実測する。
> **背景**: この環境は変換率 4.3%・write-only advisory 18個の「観測厚く作用薄い」体質。Phase 1-3 はどれも観測機械を足す側なので、先に「作用に変換されるか」を安く検証する（[[cross-pj-distillation-concept]] §5 over-eng 点検結論）。

## 何を測るか（2026-07-08 精密化）

過去ログ調査で判明した事実により指標を組み替えた:

- **need（横断で通じる素材の実在）は裏取り不要＝既に済み**（fleet recall + ドラフト §1 高同型9件）
- **instance（rubric/pitfalls など中身）への焼き戻しは過去から活発**（実測: bots `review_rubric.md` は 2026-06-24〜07-04 の10日で **9 commit**）
- **型スキル4個は 07-06〜07 作成後、焼き戻し 0 回**（作成時刻＝最終更新時刻・`~/.claude` は git 管理外）
- → 過去ログから「型への焼き戻し」は**原理的に取れない**（型スキルが新しすぎる）。全PJログ網羅解析は over-eng 点検で保留した観測機械づくりへの逆戻りなので**やらない**。

**唯一の未知数** = instance はこれだけ活発に育つのに、その知見が**型（global skill）まで昇格**する行動が起きるか、の一段。**主指標を「昇格漏れ」に変更**する。

## パイロット設計

- **開始 / 起点**: 2026-07-07（型スキル4個 = 焼き戻し0回 / instance = 活発 のギャップが出発点）
- **判断点（実質）**: **2026-07-21**（中間チェックを判断点に格上げ）
- **最終アウターバウンド**: 2026-08-04
- **対象型スキル**（4個）と各インスタンス PJ:
  - `evaluation-loop-method` ← explainer-script-method / figma-to-code(figma-eval-expert)
  - `correction-to-permanent-ledger` ← explainer / figma(pitfalls) / evolve-anything(pitfall-curate)
  - `ground-truth-over-summary` ← explainer / figma / evolve-anything(representative)
  - `explainer-script-method`（既存の型としても観測対象）← zundamon / kuni-isle
- **やること**: 上記いずれかの PJ で作業中に correction / 修正指摘に気づいたら、下の観測ログに1行。特に「instance（中身）は直したが、型（global）には上げなかった」ケースを**昇格漏れ**として記録する。
- **主指標 = 昇格漏れ回数**: instance を焼き戻したのに型へ上げなかった回数。
- **副指標 = 型への焼き戻し回数**: 型スキルの SKILL.md を実際に編集した回数。
- **判定**（7/21 判断点）:
  - **型焼き戻し 0 かつ 昇格漏れ 0** → 横断で通じる指摘がそもそも発生していない。継続 or 打ち切り。
  - **型焼き戻し 0 かつ 昇格漏れ ≥1** → 「可視化しても型へ上げない」＝観測とアクションの断絶が実証。Phase 1 自動化の前提が崩れる（＝作らない確定の補強）。同時に「昇格を促す最小の仕掛け」の要否を別途検討。
  - **型焼き戻し ≥2** → 型へ昇格する行動が現に起きる。Phase 1 帰属レーン or L4+ 配線の投資対効果を再検討（速断しない）。
