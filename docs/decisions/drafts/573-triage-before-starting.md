## 1. 完成条件（round 0・verbatim 転記。頭の指示によりここは再検討しない）

①**守る対象**: 「実需要（守る対象の件数・使う人の数）が実測0件の作業を、最優先で着手する」判断が、この rule を通すと止まること。
②**信頼境界（誰の能力を脅威に数えるか）**: 攻撃者・悪意ある第三者は数えない。脅威は (a) AI 自身が重要度を誤判定すること (b) rule が存在しても発火しないこと (c) 発火条件が語句依存で、言い換えによって回避できること。
③**対象外**: 個別PJの優先順位そのものの正しさ／既存 rule の書き換え（衝突が出たら指摘として受ける）／hook・skill による機械強制（今回は rule のみ）／着手後の進め方（既存 rule の担当）。
④**blocking の定義**: ①が破れる経路を構成できること／②(c) の言い換え回避が成立すること／**今すぐ着手すべきもの（他者待ちでリードタイムが自分の手の中に無いもの・新機能やMVPなど対象外に該当するもの）を誤って止めること**（＝偽陽性も blocking）。
⑤**検証方法**: 隔離ワーカーによる A/B 比較（rule 無し／有り、#437 と同じ状況を与える）＋ 発火判定の断片テスト（陽性4件以上・陽性対照2件以上）。**実測は頭が実施する**（本文書は測定計画のみ）。

**rev4 での①の解釈補足**（③対象外・rule 修正なしの範囲内）: rev4 は0/非0の閾値を「実測規模と代替手段コストの比較」へ一般化したが、これは①「実需要0件の最優先着手を止める」を包含する特殊ケースとして扱う（実需要0件なら代替コストはほぼ常に既存の粗い手段以下になり、比較の結果として着手しない側に倒れる）。

## 2. rule 全文案

**ファイル名案**: `~/.claude/rules/triage-before-starting.md`
**箇条書き項目数**: 10（frontmatter・見出し・空行は含まず。10以内の上限ちょうど。実装時に子bulletへ展開して増やさないこと＝codex I5 Nit への対処として、実装受入条件を「本ブロックを verbatim で配置する」に固定する）

```markdown
# 着手前トリアージ（防御・復旧・保険機構の需要を測らず最優先化しない）
- **適用対象（構造で限定する。名称・自己申告ではなく主目的と期待効果で判定する）**: 「その作業が無かったときに何が起きるか」で分類する。**起きるのが損失の回避（防御・復旧・保険・堅牢化・予防）なら対象内、新しい価値の提供（新機能・MVP）なら対象外**。「防御」「MVP」等の呼び名を自己申告した時点で分類を確定しない。ユーザーが明示的に依頼したタスク・現在進行中の障害対応は対象外（対象外には本 rule のいかなる義務も課さない）
- **発火条件（構造で定義する。語句や「新規/継続」の区別で判定しない）**: 上記対象について重要度・優先度・着手可否を判断する時点で適用する。issue 起票／worktree 作成／委譲プロンプト執筆／それらを介さない実装・設計文書の編集開始／**Read・Bash だけで進める相談・レビュー応答・既存文書上での判断更新**／**既存 issue の継続・中断作業の再開**／「着手する」の宣言、のいずれか最も早いものが発火点
- **測定義務**: 着手前に、母集団（何を1件と数えるか）を1行で固定したうえで守る対象／使う人の実測規模を書く。`factual-claims.md` の要件（再現手段・取得時刻・除外条件の併記）を満たせない数値は書かず、測定不能と判定するときは `measure-now-not-later.md` の3問に答えてから測定不能と書く（測定不能を「着手してよい」の根拠にしない）
- **判定義務（主柱）**: 実測規模と、**既存のより粗い代替手段（フルリストア・手動運用等）のコスト**を1行で比較し、代替で足りるなら着手しない。**加えて、提案する機構自体の実装・運用コストと実測規模を1行で比較する**。**代替手段が無いことだけでは着手資格を解除しない**（代替が無くても実測規模が0件なら、機構コストに対して需要が見合わず着手しない）。**判定は0/非0の閾値ではなく2つの比較の結果で決める**（規模が1件以上でも代替で足りれば着手しない。規模が0件なら代替の有無にかかわらず着手しない。他者待ち例外はこの判定に関係なく従来どおり適用される）
- **誤った代理指標を禁じる**: 以下を単独で「重要だ・最優先だ」の根拠にしない — レビューで重大な欠陥が出たこと（欠陥の重大さ ≠ タスクの重要さ）／設計が難しいこと／安全・データ保全に関わること（上の比較義務を経ずに安全性だけで着手を正当化しない）
- **不着手時の記録**: 着手しないと判定したら、判定根拠を成果物の「トリアージ記録」節（無ければ先頭に新設）へ記し、保留していた元のタスクへ即座に戻ることを次アクションに明記する（再開条件・実行契約の書式は `measure-now-not-later.md` を参照し、ここで再定義しない）
- **着手資格と優先順位の分離**: 上の判定で着手してよいとなっても、それは着手資格の解除に過ぎず優先順位を認可しない。優先順位は既存の PJ 優先順位 rule に従う
- **例外（他者待ち）**: 分類は `provisional-over-blocker.md` を参照する（ここで再定義しない）。適用時は待っている相手・依頼内容・**自分が設定するフォロー期限**（相手が返答期限を約束しない場合も自分側の再確認予定として設定する）を成果物へ明記する。**依頼を投げる行為自体は即座に許可**し、回答が来た後の実装着手判断は上の測定・判定義務に従う
- **本 rule は着手後の順序・巡数・進め方、および PJ 側の優先順位 rule の境界裁定を扱わない**（`pillars-before-polish.md` 等、個別 PJ の健全性判定の明確化は本 rule の対象外・別途 issue で扱う）
- 出所: 2026-08-27 updater-index #437（守る対象が実測0〜6件の復旧機構を最優先で設計2巡・レビュアー4本ぶん回した後にユーザー指摘で判明）。PJ横断のユーザー指摘「すぐ対応が必要、という判定をしてしまって骨子のタスクが進められない」。A/B v2 arm A の実測（`573-ab-measurements.md`）で、実測を宣言するだけでは着手可否が変わらないことを確認した。**実測（隔離ワーカー・各 n=1・2026-08-27）**: rev4 で A/B を取り着手可否が反転（続行→縮小）、発火判定は陽性4/4・陽性対照4/4。rev5 の2修正は追加3断片 3/3 で確認した。**未実測**: 実運用での効果（適用対象の限定・比較義務・例外のフォロー期限のいずれも、実際の作業で発火して着手順が変わるかは測っていない）
```
