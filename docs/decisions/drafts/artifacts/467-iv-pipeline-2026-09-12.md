## この分解から言えること／言えないこと

**言えること（観測）**

- **判定器に実際に掛かった correction は 75 件中 3 件**。0 件という産出は、判定器が
  何かを取りこぼした結果ではなく、**入口の 8 件がさらに 3 件まで削れた結果**である
- `plugin:skill` 形式の解決は**本番経路では機能している**（3/3 解決）。前 artifact の
  「解決 0」は計測スクリプト側の旧規則による値であって、本番の状態ではない
- 4件の脱落理由は `readable-report` の**実体が main で廃止済み**であること（1 スキルに
  correction が4件集中していた）。`status-recap` は実体があるが critical 行が 0 で、
  判定器の対象になっていない

**言えないこと**

- 3 件で違反 0 だったことから、判定器の再現率・精度は評価できない（標本が小さすぎる）
- 「A 案で朝の y/n に何件届くか」は本分解では出ない。届く件数は S1 の増え方に律速され、
  S1（`last_skill` truthy）は当PJで 8/75 にとどまる

## 安全性検証

`write_guard`（`measure_467_proposal_kinds.py` の execution-time monkeypatch を再利用）
と `~/.claude/` マニフェスト差分。LLM 呼び出し 0。

- 段階分解の区間: `write_guard=passed` / `network_guard=passed`（socket・子プロセスとも全ブロック）
- `cross_check` の区間: `run_discover()` は本番経路として子プロセスを起動するため、
  **socket だけ塞ぎ、起動した子プロセスの argv を verbatim で記録する**方式に切り替えた
  （名前の列挙で許可・拒否を判定しない）。記録されたのは
  **`git rev-parse --git-common-dir` の1件のみ**（JSON の `cross_check.subprocesses_spawned`）。
  `write_guard=passed`
- **マニフェスト差分に無関係な PJ の transcript jsonl が `changed` として出るが、これは
  並行して動いている別の Claude Code セッションが会話を追記しているもので、本スクリプトの
  書込みではない**（スクリプト自身の書込みが無いことは execution-time の
  `write_guard=passed` が示す。マニフェスト差分は補助的な証跡）
