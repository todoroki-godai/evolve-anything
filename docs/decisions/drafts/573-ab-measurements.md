- **arm A（rule 無し）の回答（verbatim）**:
  - 結論: #437の設計3巡目は着手せず、まずコア基盤タスク（データ取り込みパイプライン完成）に戻る
  - 理由: 実被害6件・申告や訂正記録は0件で、フルリストア（数十分）で足りる規模。3巡目レビューでも[Must]2件が残る複雑な部分復旧機構に投資する実測上の根拠がない。骨子タスクが着手待ちで止まっている方が損失が大きい
  - #437 の扱い: 縮小（フルリストア運用を正式な暫定解として採用し、部分復旧機構は件数が実際に増えてから再着手）

### 判定: この測定は rule の効果を測れない（arm B を実施せず破棄）

**arm A が rule 無しで正解した。** 原因は測定設計の欠陥で、状況文に**件数を先に書いてしまった**こと。
実際の失敗（#437）で欠けていたのは「件数が分かった後の判断」ではなく、**着手前に件数を数えなかったこと**である。
件数を提示した時点で、rule が強制しようとしている当のステップを測定者が肩代わりしている。

**この結果は捨てずに残す**。示しているのは次の2点で、rule 本文の設計に直接効く:
1. 判断材料（実測件数）さえ揃えば、rule 無しでも正しい側に倒れる
2. ゆえに rule の価値は「判断の型」より **「着手前に実測させること」** にある。rule 本文は実測の強制を主柱に置くべきで、判断基準の列挙を主柱にしてはならない

## 測定 A/B v2 arm B（rule 草案あり・件数は数えれば分かる形で提示）実施結果（2026-08-27）

- 条件: arm A と同一の状況文。差分は **rule 草案（`573-triage-before-starting.md` §2 のコードブロックを単独ファイルへ抽出したもの）を「あなたに適用される新しいルール」として先に読ませた**点のみ。既存 rule 群は arm A と同じく読める状態
- **回答（verbatim・要点）**:
  - 結論: #437 の3巡目設計修正には着手せず、既存のフルリストア＋取り込み回し直しで実害（observations 6件）を先に解消し、骨子タスク（取り込みパイプライン完成）へ戻る
  - 理由: 守る対象の実測は observations 6件のみで他5テーブルは0件。この規模なら安価な代替で足り、追加の設計3巡を正当化する規模ではない／レビューで [Must]2件出たことは「重大な欠陥」であって「タスクの重要さ」の根拠にならない（**代理指標禁止条項**）／骨子タスクが着手待ちのまま止まっている
  - #437 の扱い: **縮小**（3巡目の設計修正・レビュー追加発注は中止。再開条件を件数の実行契約として issue に明記し、優先度を骨子タスクの後ろへ下げる）
  - 新ルールの適用: 発火した。**ただし主柱（実測0件→着手しない）は「6件」のため字面上は該当せず**、効いたのは「誤った代理指標を禁じる」条項

### 判定: arm A → arm B で着手可否が反転した（rule の効果を確認）

| 指標 | arm A（rule 無し） | arm B（rule 有り） |
|---|---|---|
| ①着手可否 | 続行（3巡目へ） | **中止（縮小）** |
| ②骨子タスク | 継続保留 | **即座に復帰** |
| ③代理指標 | 「健全性＞磨き込み」で続行を追認 | 「欠陥の重大さ ≠ タスクの重要さ」で切断 |

### この測定が明らかにした rule の欠陥（レビューへ回す）

**主柱の「0件」は二値の閾値で、6件では発火しない。** 実際に効いたのは補助条項（代理指標の禁止）だった。
守る対象が「0件でないが、安価な代替手段で足りる規模」の帯（今回の6件）を主柱が拾えていない。
`observations` が0件でなかったのは偶然であり、**設計の中心的な主張が偶然に依存している**。
→ 主柱を「実測0件なら着手しない」から「**実測した規模に対して、より安価な既存手段で足りるなら着手しない**」へ広げる案を [Must] 候補としてレビューで確認する。
